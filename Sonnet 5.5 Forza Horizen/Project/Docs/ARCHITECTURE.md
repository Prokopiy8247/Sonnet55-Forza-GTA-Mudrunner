# Architecture contract — "Roamline: Open Roads" (UE 5.8.2, C++)

Binding for every implementing agent. Prefix of all game classes: **`Roam`**. Content root: `/Game/Forza/...`. Runtime module `Sonnet55Forza` (API macro `SONNET55FORZA_API`), editor-only module `Sonnet55ForzaEditor`.
Code style: UE conventions (U/A/F/E/I prefixes), `#pragma once`, minimal includes in headers (forward declare), no Blueprint-only assets. Everything data-driven (data assets / DataTables / JSON → data assets built by editor scripts). **No tick spam**: subsystems own logic; actors only when they need a transform.

## 3. Key classes & responsibilities (public API that other systems may call)
* `URoamCarDefinition : UPrimaryDataAsset` — id, display name, class label, PI, drivetrain, mesh refs (soft: Body, Glass, Interior, SteeringWheel, Wheel FL/FR/RL/RR), geometry (wheel centres, radii, track, wheelbase, cameras, light anchors — from the Blender JSON), mass & inertia, COM offset, engine (torque curve `FRuntimeFloatCurve` or sampled array, idle/redline RPM, inertia, friction, turbo), gearbox (ratios, final drive, shift RPM, shift time), drivetrain split & differential (open/LSD/preload, AWD front-rear split), brakes (max torque, bias), suspension (per axle: spring rate, damper bump/rebound, travel, anti-roll, camber gain), tyres (per surface grip peaks/slide ratio, load sensitivity, width), aero (Cd·A, Cl·A front/rear, active wing optional), steering (lock deg, speed-reduction curve, assist), sound profile (cylinders, base RPM-pitch, harmonic mix, turbo whine, exhaust crackle), upgrade slots, price/credits.
* `URoamCarCatalog : UDataAsset` — ordered list of the 10 `URoamCarDefinition`.
* `ARoamVehicle : APawn` — see §4. API: `ApplyCarDefinition()`, `SetPaint()`, `GetTelemetry()`, `ResetToRoad()` (nearest road point, upright), `FlipUpright()`, `SetAssist(name,bool)`, `SetCameraMode()`, input functions (`SetThrottle`, `SetBrake`, `SetSteer`, `SetHandbrake`, `ShiftUp/Down`), `SetAIControlled(bool)` for tests.
* `URoamTimeWeatherSubsystem : UWorldSubsystem` — `GetGameHour()/SetGameHour()`, `SetTimeScale()`, `GetWeather()/SetWeather(ERoamWeather, blendSeconds)`, `GetWetness()` (0..1, surface wet state with hysteresis), `GetRainIntensity()`, `GetFogDensity()`, `GetGripMultiplier(ERoamSurface)`, `GetVisibilityKm()`, delegates `OnWeatherChanged`, `OnHourChanged`. No visuals.
* `ARoamSkyManager : AActor` — day/night + weather visuals (DirectionalLight sun/moon, SkyAtmosphere, VolumetricCloud, ExponentialHeightFog, SkyLight real-time capture, post-process, rain/storm FX, lightning, wet-surface Material Parameter Collection updates, street/vehicle light time-of-day signal). Driven from the subsystem.
* `URoamRoadNetwork : UDataAsset` + `FRoamRoadQuery` — built from `roads.json` by the editor module. `FindNearest(Location, ClassMask) -> FRoamRoadHit{RoadId, S, Pos, Tangent, Right, Surface, Distance}`, `SamplePosition(RoadId,S)`, `FindRoute(A,B)` (A* on junction graph), lanes: `LaneOffset(road, laneIndex)`, speed limit.
* `URoamTrafficSubsystem : UWorldSubsystem` — lane graph, spawning/despawn/pooling, density (`SetDensity(0..1)`), LOD (physics near, kinematic mid, none far), reaction to collisions.
* `URoamActivitySubsystem : UWorldSubsystem` + `ARoamActivityActor` subclasses placed by the editor builder from `worlddef` data. Notifications go through `URoamUISubsystem::PushNotification(Title, Body, Colour, Seconds)`.
* `URoamConsoleSubsystem : UGameInstanceSubsystem` — `RegisterCommand(FName Name, FText Help, FRoamConsoleFn Fn)`, `Execute(const FString&) -> FString`, history/log buffer. Each system registers its commands in `Initialize()`; no system depends on the UI to be testable.
* `URoamUISubsystem : UGameInstanceSubsystem` (or owned by `ARoamHUD`) — creates/destroys Slate widgets (HUD, minimap, console, garage, debug, map, photo overlay, notifications), routes input mode changes (game vs UI), exposes `PushNotification`, `ShowRegionName`, `ToggleConsole/Garage/Debug/Map`.
* `URoamSaveSubsystem : UGameInstanceSubsystem` — `SaveProfile()/LoadProfile()`, slot "Profile".

## 4. Vehicle model (decision: project-owned raycast/spring vehicle on a Chaos rigid body, NOT Chaos Vehicles)
Why: full control of tyre/drivetrain/assist behaviour, data-driven, deterministic, stable at 250+ km/h via sub-stepped custom forces, no dependency on the experimental plugin; collisions/damping still handled by Chaos on the body's simple collision (UCX hulls).
* Root = `UStaticMeshComponent* Body` (simple convex collision from `UCX_` hulls, mass/COM/inertia overridden from the data asset, CCD on, `bSimulatePhysics`, linear/angular damping ~0, sleeping off). Wheels = separate visual-only static mesh components attached to the body, positioned per frame from suspension state (steer, spin, camber).
* Forces applied each **physics sub-step** (custom physics callback / async physics tick per research): suspension (spring-damper along the body up axis from sphere/line traces, bump-stops, anti-roll), tyres (slip ratio/angle → combined friction ellipse, load-dependent, per-surface grip × weather multiplier, wheel angular velocity integrated, handbrake lock), drivetrain (engine torque curve & rev inertia, clutch/auto gearbox with shift logic, diff models, AWD split), brakes (+ABS), aero (drag, downforce, ground effect), anti-roll, assists (TCS, STM, ABS, steering assist), rolling resistance, surface drag.
* Wheel traces use collision channel `ECC_Vehicle`-like custom trace channel (configured in DefaultEngine.ini: `Roam_Vehicle` object channel, `Roam_Wheel` trace channel); road/landscape/props respond Block; traffic cars block `Roam_Vehicle` only.
* Surface lookup: `UPhysicalMaterial` assets `PM_Roam_*` (project-owned, created by script) mapped to `ERoamSurface` through `SurfaceType1..8`; landscape layers get the matching physical material per layer; static meshes (roads) get theirs via material or component override.
* Telemetry struct is filled each frame for UI/audio/FX; automated drive tests use `SetAIControlled(true)` + scripted inputs.

## 5. UI approach
Slate in C++ (custom `SLeafWidget`/`SCompoundWidget`, `OnPaint` drawing with `FSlateDrawElement` for gauges, minimap, graphs) added through `GEngine->GameViewport->AddViewportWidgetContent`. No UMG blueprint assets. Original visual language: dark glass panels + bright accent (festival orange/teal), clean sans font from engine (Roboto), no Forza artwork.

## 6. World building (editor module + Python)
`Tools/world/build_world.py` produces data (heightmap/weightmaps/roads.json/placements). Blender builds geometry from `roads.json`. The editor module exposes BlueprintCallable functions used by `Tools/ue/*.py`: `CreateLandscapeFromHeightmap`, `ImportRoadNetworkJson -> URoamRoadNetwork`, `SpawnInstancedScatter`, `CreateDataAssetFromJson`, `BuildWorldPartitionMap`, etc. Python orchestrates; every step is re-runnable.

## 7. Collision / physics channels, tags, naming
* Object channels (DefaultEngine.ini): `Roam_Vehicle` (ECC_GameTraceChannel1), `Roam_Traffic` (…2), `Roam_Pickup` (…3). Trace channels: `Roam_Wheel` (…4), `Roam_Camera` (…5). Profiles: `RoamVehicle`, `RoamTraffic`, `RoamWorldStatic`.
* Actor tags: `RoamRoad`, `RoamDrivable`. Asset naming: `SM_` static mesh, `M_` material, `MI_` material instance, `MF_` function, `PM_` physical material, `DA_` data asset, `T_` texture, `MPC_` parameter collection, `NS_` niagara system, `MS_` MetaSound.

## 8. Performance rules
Target 60 FPS. Tick only the player vehicle at physics rate; AI/traffic through the traffic subsystem batch tick (single tick for all). World Partition for static content; Nanite for opaque static meshes; no per-frame allocations in hot paths; pool traffic and FX; limit active physics bodies (traffic physics only near the player and only after a hit).

## 9. Testing
* Build: `Tools/build_editor.ps1`. Python smoke: `Tools/ue_cmd.ps1 -PythonScript ...`. Game run: `Tools/ue_cmd.ps1 -Game -Map ... -ExecCmds ...`. Automation tests live in `Source/Sonnet55Forza/Tests` and run headless with `Automation RunTests Roam`. Exact commands and troubleshooting: `Docs/Tech/BUILD_AND_RUN.md`.

## 10. Skeleton (implemented state) — what exists, what changed versus sections 1-9
The C++ skeleton is built, compiles warning-free (own code) for the `Sonnet55ForzaEditor` and `Sonnet55Forza` targets, and `Automation RunTests Roam` passes (22 tests). Every header is the **final shared contract**: bodies marked `// OWNER: <agent>` are stubs with final signatures; owners fill bodies, they do not change signatures (add new members instead). Ownership map:

| Area | Files | Owner |
|---|---|---|
| Vehicle physics | `RoamVehicleMovement` (`StepPhysics`, `AsyncPhysicsTickComponent`), `RoamVehicle` (OWNER stubs: damage/repair visuals) | vehicle-physics agent |
| Camera + audio | `RoamCameraRig`, `RoamEngineSynth` | camera/audio agent |
| Vehicle visuals + FX | `RoamVehicleVisuals` (paint/lights/wheel anim), `RoamVehicleFX` | vehicle-visuals / effects agent |
| Sky + weather visuals | `RoamSkyManager` (the logic in `RoamTimeWeatherSubsystem` is DONE and tested) | sky/weather agent |
| Traffic | `RoamTrafficSubsystem`, `RoamTrafficVehicle` | traffic agent |
| Activities | `RoamActivitySubsystem`, `RoamActivityActor` | activities agent |
| UI (Slate) | `RoamUISubsystem::CreateWidgets/DestroyWidgets` (state machine, notification queue, panel switching are DONE), `RoamHUD` canvas shell is the placeholder | UI agent |
| World/regions | `RoamRegionSubsystem` (polling + popup + teleport resolve DONE; richer region logic OWNER) | world/regions agent |
| Done in the skeleton (change only by agreement) | `Core/*`, `Data/*`, `Console/*`, `Save/*`, `World/RoamTimeWeatherSubsystem`, `Sonnet55ForzaEditor/RoamEditorLibrary` | lead |

**Shared contracts a newcomer must know**
* **Console.** `URoamConsoleSubsystem` + `ROAM_REGISTER_CONSOLE_COMMAND("name", "usage", "help", [](const FRoamConsoleContext& Ctx) -> FString {...})` anywhere in the module (static registrar, no shared file to edit; `..._CATEGORY` variant for `help` grouping). Handlers get `World/GameInstance/PlayerController/Args` and `GetInt/GetFloat/GetBool/Fail`. Built-ins: `help commands echo clear history version delay ue`. From the UE console: `roam <cmd>`; the UE console key moved to **F10**, the backtick/tilde key opens the Roam console (UI owner). `-ExecCmds` splits on commas and executes everything in frame 1, hence `roam delay <s> <cmd>`; `roam ue <engine cmd>` goes through the player controller (viewport commands such as `HighResShot` need it).
* **Settings and data.** `URoamSettings` (Project Settings > Game > Roamline; `Config/DefaultGame.ini`) holds soft references to `DA_CarCatalog`, `DA_RoadNetwork`, `DA_WorldDefinition` and the default vehicle class; `URoamGameInstance` lazy-loads them (`GetCarCatalog()/GetRoadNetwork()/GetWorldDefinition()`, missing assets are a Log message, never an error: the map runs without data). `PhysicalMaterialToSurface` maps `PM_Roam_*` to `ERoamSurface`.
* **Spawning.** `ARoamGameMode::RestartPlayer` picks saved transform > POI > road > PlayerStart > origin, drops to the ground with a `Roam_Wheel` trace, and spawns `ARoamVehicle` (deferred; `InitialCarDefinition`). API: `SpawnPlayerCar(Def, Transform)`, `SpawnPlayerCarAtCurrent(Def)`. Console: `cars car respawn reset flip paint assist camera`.
* **Telemetry** is `ARoamVehicle::GetTelemetry()` (filled by the movement component, forwarded in `PublishTelemetry`). Driver inputs: `SetThrottle/SetBrake/SetSteer/SetHandbrake/ShiftUp/ShiftDown`, `SetAIControlled(true)` for scripted tests (`drive <throttle> [steer] [brake]` console command).
* **Time/weather** (`URoamTimeWeatherSubsystem`, `FRoamTimeWeatherModel` pure model for tests): `TimeScale` = game seconds per real second (default 30), sun angles by declination/hour angle, wetness has hysteresis (on at 0.30, off at 0.12; wets at Rain/45 s, dries at (0.3+0.7*sun)/300 s), weather blends with smoothstep, optional seeded auto-scheduler. Grip: `Roam::SurfaceGripMultiplier(Surface, Wetness)` (asphalt 1.00 dry / 0.72 wet / 0.62 soaked; dirt 0.78/0.55/0.45; gravel 0.70; grass 0.60; sand 0.55; snow 0.35). Commands `time timescale weather wetness grip`.
* **Save.** `URoamSaveSubsystem` (profile, slot from settings): `LoadProfile/SaveProfile/AsyncSave/ResetProfile`, `CaptureRuntimeState/ApplyRuntimeState`, `SubmitPersonalBest/SubmitStars/AddXp/MarkCollected`, per-car paint. Commands `save load resetprofile profile`.
* **Road network** (`URoamRoadNetwork`, `Data/RoamRoadNetwork.h`): `FindNearest`, `FindNearestRoad`, `FindNearestOnRoad` (windowed, cheap per-frame tracking), `SamplePosition`, `LaneOffsetCm`, `FindClosestLane`, `FindRoute/FindRouteBetween` (A* on the junction graph), `BuildRoutePolyline`, `Validate`; `BuildGeneratedForTests()` makes a synthetic network for unit tests/test maps.
* **Car data** (`URoamCarDefinition`): `ComputePerformance()` = the PI formula (below), `GetPerformanceIndex/GetCarClass/GetClassLabel/GetEstimatedInertia/Validate/ToDebugString`. `URoamCarCatalog::ResolveCar` accepts 1-based index, id or unique substring.

**Deviations from sections 1-9 (the doc above is the original contract; this is what was actually built)**
1. *Layout (sec. 1).* Files that the plan listed but that were folded in: `RoamTireModel`, `RoamDrivetrain`, `RoamRoadQuery`, `RoamLaneGraph`, `RoamPhysMatLibrary`, `RoamSurfaceLibrary`, `RoamUpgradeDefinition` do NOT exist as files (tyre/drivetrain code lives inside `URoamVehicleMovement`/its future helpers, road queries are members of `URoamRoadNetwork`, upgrade slots are `FRoamUpgradeSlot` in `RoamCarDefinition.h`, surface helpers are in `namespace Roam` in `RoamTypes.h`). Added instead: `Core/RoamCollision.h` (channel/profile/tag name constants), `Vehicle/RoamVehicleVisuals` (planned in sec. 1 but not described in sec. 3), `Save/RoamSaveGame.h` carries only the thin `USaveGame` wrapper. UI Slate widgets (`SRoam*`) are not created yet (UI owner). The editor module is `Sonnet55ForzaEditor/RoamEditorLibrary` (not `RoamWorldBuilder`; the builder functions are added to the library by the world agent).
2. *Collision (sec. 7).* The two TRACE channels `Roam_Wheel` and `Roam_Camera` **default to Ignore** (the intuitive choice - Block - was tried first and fails): with Block, spectator/pawn capsules intercepted the wheel rays (a SpectatorPawn was hit at z=155 and the car spawned on top of it). Only `RoamWorldStatic` explicitly Blocks `Roam_Wheel/Roam_Camera/Roam_Vehicle/Roam_Traffic`; anything the wheels should drive on must use that profile (or answer Block to `Roam_Wheel`). A fourth profile `RoamPickup` exists (overlap `Roam_Vehicle` only).
3. *Telemetry (sec. 2).* The per-wheel arrays `WheelSlipRatio[4]`, `WheelSlipAngleDeg[4]`, `WheelLoadN[4]`, `WheelOnGround[4]` are plain C++ members, NOT `UPROPERTY` (UHT forbids static/bool arrays in Blueprint-visible structs); they are not available to Blueprints/Python. `FRoamProfile` has every member flagged `SaveGame` (only those are serialised, including nested struct members) and carries `FRoamPlayerSettings` (units, HUD toggles such as `bShowSpeedometer`, ...) and `FRoamAssistSettings`.
4. *Car definition (sec. 3).* Torque curve is `TArray<FRoamTorquePoint>` (RPM, Nm) rather than `FRuntimeFloatCurve` (deterministic, testable without curve assets; `BuildSyntheticTorqueCurve` generates one from peak power/torque). Tyre `SurfaceBias` is a per-`ERoamSurface` multiplier on top of the base friction (not an absolute peak). Default wheel layout in `FRoamCarGeometry` is wheel centres (+-130, +-77, 33) cm: left wheels have NEGATIVE Y (UE +Y = right).
5. *Road network (sec. 3).* Lane convention: signed lane index, `+1,+2..` are forward lanes on the RIGHT of the road direction (right-hand traffic), negative are oncoming; positive bank lowers the right side. Roads are split at junctions, A* runs on a junction graph with virtual start/end nodes; class cost factors highway 1.0, regional 1.25, mountain 1.8, dirt/shortcut 2.5, village 1.4. The spatial grid is rebuilt in `PostLoad`/`BuildSpatialIndex()` (not serialised).
6. *Save (sec. 3).* Beyond `USaveGame` the subsystem wraps the payload in an integrity envelope `"ROAM" | version | size | CRC32 | payload` and validates it BEFORE the engine loader runs: `UGameplayStatics::LoadGameFromMemory` hard-asserts on garbage bytes in 5.8.2 (FName length overflow), so a corrupt file would crash the game instead of resetting the profile.
7. *Input (sec. 3/5).* Enhanced Input assets are created at RUNTIME (`NewObject` actions + mapping contexts, no assets on disk): `Gameplay` context priority 0, `System` context (console/menu/camera keys) priority 10. Axis values are polled in `PlayerTick`; mouse look only with the right mouse button held or the right stick. 16 actions in `ERoamInputAction`.
8. *Physics stepping (sec. 4: 'custom physics callback / async physics tick').* Decided and measured: **async physics tick at fixed 120 Hz** via `UActorComponent::AsyncPhysicsTickComponent` (`bTickPhysicsAsync=True`, `AsyncFixedTimeStepSize=0.008333`), NOT `FBodyInstance::AddCustomPhysics` (a once-per-frame call in Chaos). Sub-stepping is configured but inert while async is on. Evidence and engine source references in `Docs/Tech/BUILD_AND_RUN.md` section 5; measured `steps=1196 avgHz=120.0 minDt=maxDt=0.00833` over a 10 s run (and 4820 steps in 40 s), independent of the render frame rate. The Chaos Vehicles plugin is NOT enabled.
9. *Vehicle placeholder (SUPERSEDED: the raycast/spring physics model is implemented, `ERoamVehicleSimMode::Physics` is the default; model, measured drive tests and tuning guide in `Docs/Tech/DRIVE_TESTS.md`; the text below describes the skeleton and what remains available as `KinematicPlaceholder`).* `URoamVehicleMovement` is a **kinematic bicycle placeholder** (ground follow by wheel traces, simple engine/gear/RPM so HUD, camera and audio have data): fine for demos, NOT physics. `SimMode == Physics` is where the vehicle-physics owner plugs the real model into `StepPhysics()` (called once per solver step with fixed dt). The root `Body` has no mesh until a car definition provides one; `PlaceholderBody` (engine cube) + four engine-cylinder wheels stand in.
10. *Camera.* `URoamCameraRig` is a `UCameraComponent` kept in absolute world space (the chase camera is not parented to the jittering body); chase collision = sphere sweep on `Roam_Camera`.
11. *Audio.* `URoamEngineSynth` derives from `USynthComponent` (additive synth; parameters are `std::atomic`, set from the game thread, read on the audio thread).
12. *Config.* Frame-rate smoothing is off, mouse smoothing off, FOV scaling off; the engine console key is F10. `[SystemSettings]` CVars in `DefaultEngine.ini` were each verified to exist in the 5.8.2 source (Lumen software tracing, VSM page budget/SMRT, streaming pool, Nanite pool, World Partition `wp.Runtime.BlockOnSlowStreaming`); defaults were not blindly overridden, every line is commented.

**Performance index (PI) formula** (`URoamCarDefinition::ComputePerformance`, constants in `FRoamPerformanceRules`): a deterministic longitudinal simulation (dt 5 ms, 90 s cap, upshift at 0.96 x redline, launch at 0.65 x peak-torque RPM, drive-weight fraction FWD 0.55 / RWD 0.58 / AWD 0.95) gives 0-60 km/h, 0-100 km/h and vmax (`FRoamCarPerformance`); lateral G = mu x HandlingFactor x (...), braking distance from min(1.02 mu, PeakG); `Offroad01 = clamp((loose-0.5)/0.4) x (0.6+0.4 x travel) x (AWD ? 1.1 : 1)`. Each rating is normalised with the ranges in the rules, weighted 0.22 / 0.26 / 0.22 / 0.07 / 0.13 / 0.10, then `PI = round(100 + 899 x Score^0.72)`. Class bands: D <= 500, C 501-600, B 601-700, A 701-800, S1 801-900, S2 901-998, X 999. The reference hatchback (105 kW, 1200 kg) yields 0-100 in 7.76 s, vmax 209 km/h, PI 592 (class C); the research prototype gave 587 (accepted drift, covered by `Roam.CarDefinition.PerformanceIndex`).

**Known limitations of the skeleton**
* No Blueprint assets, no Slate widgets and no content data assets exist yet: `DA_CarCatalog/DA_RoadNetwork/DA_WorldDefinition` are built later by the editor builders. Without them the game runs in 'placeholder' mode (`ROAM_SPAWN car=<placeholder>`).
* `/Game/Forza/Maps/L_Test` (4 km flat ground, 5 degree ramp, sun/sky/fog, PlayerStart) is generated by `Tools/ue/make_test_map.py`; it is a test map, not the world.
* Traffic, activities, region logic, sky visuals, engine audio, vehicle FX and UI widgets are documented stubs (commands `traffic`, `act.list`, `ui`, `notify`, `tp`, `regions` already work against them).
