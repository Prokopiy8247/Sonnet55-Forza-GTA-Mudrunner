# Nature kit - TREES (21 assets + 21 far cards)

Generated by `Tools/blender/nature/make_trees_doc.py` from the exported sidecars (`Exports/Nature/Trees/*.json`). Source of truth for geometry: 
`Tools/blender/nature/trees.py` (asset table + harness) + `treelib.py` (geometry core) + `tree_fams.py` (family builders). Every asset is generated procedurally and idempotently from a seed.

## 1. Conventions
* Units: 1 Blender unit = 1 m. Z up. **Origin = trunk base centre on the ground (z = 0).** Roots / trunk base are buried 0.3-0.5 m below z = 0 so the tree sits on uneven terrain. Transforms are applied (scale 1, rotation 0, verified).
* One FBX per asset: `Exports/Nature/Trees/<id>.fbx` = tree mesh `<id>` + trunk collision hulls `UCX_<id>_NN`; plus `<id>_Far.fbx` (distance card) and `<id>.json` sidecar. FBX written with the project recipe (`Tools/blender/lib/fbx_export.py`, `center_on="self"`, axis -Y/Z, unit scale applied -> UE centimetres), **vertex colours exported LINEAR** (raw masks, no sRGB conversion).
* FBX re-import round-trip verified (origin at 0,0,0, correct size, `Col` + `UVMap` + material names preserved).
* All opaque geometry (Nanite friendly). No alpha cards inside the tree mesh; leaf / needle "cards" are real single-sided folded geometry (2-8 tris each), so use **two-sided** materials (or Nanite two-sided foliage) on `M_Tree_Leaf*`, `M_Tree_Needle`, `M_Tree_Palm`.
* Import normals from the FBX (custom "ball" normals on foliage give soft crown shading): Static Mesh import -> *Normal Import Method = Import Normals*, tangents = MikkTSpace.

The contract lists 5 tree materials (`M_Tree_Bark`, `M_Tree_Leaf`, `M_Tree_Needle`, `M_Tree_Palm`, `M_Tree_Dead`); `M_Tree_Bark_Birch`, `M_Tree_Bark_Dark`, `M_Tree_LeafLight`, `M_Tree_LeafDry` were added because white birch bark with black marks and the lighter / grey foliage cannot be expressed by one shared instance. ## 4. Vertex colours = wind (attribute `Col`, exported LINEAR)
* **R = branch flex** 0 at the trunk base -> ~0.2 at the fork -> 1 at twig / leaf tips (hierarchical: a branch inherits the value where it leaves its parent).
* **G = leaf flutter** 0 on wood -> ~0.3 at the base of a leaf card -> 1 at the free tip; leaf-mass cores ~0.1.
* **B = baked ambient occlusion** (real ray-cast AO inside the tree, 1 = open sky, floor 0.16; one sample per leaf card). Multiply base colour by `lerp(0.35, 1, B)` and/or feed Lumen-free ambient.
* UE material hint: `WPO = windDir * (R^2 * lowFreqSway + G * highFreqNoise)`; trunk base (R=0) never moves.

## 5. Collision
* `UCX_<id>_NN`: convex hulls (<= 32 verts, verified convex + closed) around the **trunk only** (capsule-like, lower 3-7 m of the trunk, flared at the base). **One hull per stem**: `tree_birch_b` has 3 hulls (3 stems), `tree_olive_c` 2 hulls (split trunk); palms get 2 stacked hulls following the curved trunk. **Canopy / foliage has no collision.** The validation report records `ucx_cover_pct` = share of bark vertices at 0.35-1.0 m height that lie inside a hull box (+12 cm); every tree is >= 94 %, multi-stem trees 100 %.
* UE: import with *Auto Generate Collision = off* (the UCX hulls are used), Collision Complexity = **Use Simple As Complex**, preset BlockAll (or a custom `Foliage` profile: block Vehicle + Pawn, ignore Camera). Mass / physics: static, never simulate.
* Hull radius is ~0.88-0.95 of the real trunk radius at that height so a vehicle clipping bark does not feel an invisible wall.

## 6. Far cards (`<id>_Far`)
* Two crossed vertical quads (4 tris, UV 0-1) centred on the trunk, width = crown diameter, height = tree height, origin at the base centre. Texture = software-rasterised silhouette + colour of the actual tree from two orthogonal views, atlas `[view along +Y | view along -X]` (left half on the X-Z quad, right half on the Y-Z quad), RGBA with alpha. **Every atlas is power-of-two** (each half-view canvas is a POT rectangle that maps exactly onto its quad, so texels are slightly non-square), edge colours are bled into transparent texels so mips / alpha clip show no dark halo. Sizes (px): pine_a 512x512, pine_b 256x512, pine_c 512x512, oak_a 1024x512, oak_b 1024x512, oak_c 1024x512, birch_a 512x512, birch_b 512x512, birch_c 1024x512, palm_a 1024x512, palm_b 512x512, palm_c 512x256, dead_a 256x128, dead_b 512x128, dead_c 512x128, poplar_a 256x512, poplar_b 256x512, poplar_c 256x512, olive_a 512x256, olive_b 256x128, olive_c 512x256.
* Intended use: HLOD / distance impostor beyond ~120-200 m (smaller trees: 80-120 m), alpha-masked (clip ~0.33), two-sided. Nanite handles LOD0 up to there, so the cards are optional.

## 7. Recommended UE import / usage
* Static Mesh: **Build Nanite = on** for LOD0 meshes (all opaque), off for `_Far`; Generate Lightmap UVs = off; Vertex Color Import = *Replace*; Combine Meshes = off (the FBX contains the mesh + its UCX hulls, UE pairs them by name).
* Use Instanced Foliage / PCG with the scale range from the table, random yaw, small random pitch (<= 3 deg), `Align to Normal` off for trunks (trees grow vertical), sink 0-10 cm.
* Do not scale non-uniformly; scaling 0.75-1.3 uniformly keeps hull / collision correct.
* Material tip: drive hue shift per instance (PerInstanceRandom) on `M_Tree_Leaf*` for variation, fade `B` (AO) in with distance.

## 10. Revision 2 - what changed after the art-director review
* **Birch (a/b/c):** the quantised square dark patches are gone. Lenticels are thin lens-shaped geometry strips lying on the real trunk surface; the foot is black ridged bark with pointed tongues rising from it (geometry, not face colouring); fork collars added; floating fill clumps pulled back to the branches; `tree_birch_c` is now a leaning, low-forking weeping birch (clearly different from `tree_birch_a`).

## 11. Known weaknesses (honest list)
* **Foliage is geometric, not textured:** leaves / needles are flat-shaded folded cards (2-8 tris) with soft ball normals. Reads well from the road and mid distance, a little stylised / low-poly in extreme close-ups. A masked leaf texture on the 0-1 card UVs in `M_Tree_Leaf*` would add the missing micro detail.
* Conifer branch sprays are "fishbone" cards on needle-sleeved twigs + a small ragged skirt per tier: believable layered silhouette, but needles are not individually modelled; the skirts are still smooth cones seen from directly above. `tree_pine_c` uses flattened radial needle-tuft pads that read as Scots-pine foliage plates from 5+ m but look a little tidy / stylised (cloud-pruned) and spiky in close-ups. `tree_pine_b` is airy: the trunk stays visible between whorls at close range.
* Crown interiors: inner branches are only visible from below / through gaps (clumps cull their inward-facing cards). Branch structure is complete under the canopy but not meant for inside-the-crown cameras.
* Wind masks are hierarchical (branch -> tip), **not** per-leaf-cluster pivot data; very large clumps sway as one unit in the vertex shader. No Pivot-Painter / per-clump pivot is baked.
* AO (B) is one ray-cast sample per leaf card and per vertex on wood; no ground-bounce / sky colour is baked.
* Bark relief is real geometry (fissures, clefts, peels, root buttresses, birch lenticels / tongues) but no normal map or albedo texture is shipped: the UE side supplies bark / leaf textures. Blender previews use procedural node materials only (voronoi cracks are preview-only).
* Palm leaflets are 6-8 tri curved strips and the fan-palm fronds are forked-tip fans, not individually split fronds; coconut clusters are 9 smooth ellipsoids hidden mostly under the fronds.
* Birch lenticels / tongues are modelled geometry (about 1-3 k tris per trunk); at very long distance they are sub-pixel and the far card carries them as speckle only.
* Only 3 variants per family (distinct silhouettes, not a continuous parameter space). More seeds can be generated from the same script by adding rows to `ASSETS`. `tree_birch_b` (multi-stem) still shows a gap between the lower and upper clump groups from some angles (bouquet read).
* Several trees are heavy (pine_b 56 k, pine_a 48 k, poplar_c 46 k, oak_c 45 k, birch_b 44 k tris): intended for Nanite; for non-Nanite platforms use the `_Far` card or add LODs.
* Collision is trunk-only convex hulls (very low-poly capsules); thick root flares beyond the hull radius are not collidable.
* Far-card textures are flat-lit colour bakes (no normal / roughness) from two views; crossed cards show view-dependent popping typical of cross billboards.
