# RENDER_SPEC — deformable ground renderer (contract for the rendering worker)

Goal: draw the whole ground (up to ~2 km × 2 km, 1 m height samples) so that **mud deformation is visible, readable and cheap**:
ruts, berms and churned mud appear as *real geometry displacement + shading*, driven by the CPU-authoritative `MudField` that the physics already writes.
Unity 6000.6, URP 17.6 (Forward), C#, hand-written HLSL. No Asset Store assets, no downloaded textures: **every texture is generated procedurally in code**.

## 1. What already exists (read these files first)
* `Assets/Game/Runtime/Ground/GroundMap.cs` — static data: `size × size` samples, `cell` metres, `origin` (world XZ of sample 0,0), `float[] height`, `byte[] weights` (size·size·8: layer weights 0..255),
  `byte[] extraDepth` (hidden extra soft depth, ×2 m), `byte[] baseWet` (0..1), `byte[] fluidity`. Layer order = `SurfaceType`: 0 Rock, 1 FirmSoil, 2 Grass/forest floor, 3 Gravel/packed dirt road,
  4 ShallowMud, 5 DeepMud, 6 Bog/swamp, 7 Sand/silt. `SurfaceDatabase.Table[i].tint` gives the debug colour of each layer.
* `Assets/Game/Runtime/Ground/MudField.cs` — dynamic deformation field. Toroidal CPU window `W=1024` cells × `cell` (0.25 m) = 256 m, mirrored in `GpuTexture`
  (Texture2D RGBAHalf, wrap Repeat, bilinear): **R = dh** (m, height offset vs undisturbed ground: negative = rut, positive = berm), **G = churn** 0..1 (disturbed/loosened/slurried mud), **B = compaction** 0..1, A = 1.
  World→texture: `uv = worldXZ * _MR_MudParams.z` (the texture repeats; world cell (cx,cz) lives at texel (cx mod 1024, cz mod 1024); texel centres at (i+0.5)/1024 ≙ world (i+0.5)·cell).
  The valid region is the window around the player: `MudField.WindowOriginWorld` .. `+WindowWorldSize` (it moves in 16 m steps); outside it the repeated texture shows wrong data — **fade displacement to zero within ~12 m of the window border** (the window centre = camera focus; pass window origin/size as shader params, or derive from `GroundService`).
* `Assets/Game/Runtime/Ground/GroundService.cs` — singleton MonoBehaviour owning `Map` + `Field`, updating the GPU texture in `LateUpdate`, and setting these **global shader properties** every frame:
  `_MR_MudField` (Texture2D), `_MR_MudParams` (x = cell size, y = window world size, z = 1/window size, w = enabled), `_MR_Wetness` (float 0..1, rain), `_MR_MapParams` (xy = map origin, z = world size, w = 1/world size).
  You must additionally publish the window origin yourself (e.g. `_MR_MudWindowOrigin` xy) — extend `GroundService` minimally for that (keep existing API intact).
* `Assets/Game/Runtime/Testing/TestArena.cs` — builds test `GroundMap`s programmatically (use it, extend it).
* Layers: `GameLayers.Terrain = 6` etc. Vehicles do NOT collide with the Terrain layer; wheels read the deformed surface analytically from `GroundMap` + `MudField`.

## 2. Deliverables (all under `Assets/Game/Runtime/Rendering/`, `Assets/Game/Shaders/`, `Assets/Editor/Rendering/`)
1. **`GroundTextures`** — procedural generation (CPU, Burst/Jobs welcome, must finish < 3 s at startup) of a `Texture2DArray` of albedo+smoothness-packed (RGBA32, sRGB) and one of normal maps (RG packed or standard normal-map, linear) with 8 slices, 1024² (mipmaps on, aniso 8), tileable (periodic noise):
   Rock (grey layered stone with cracks), FirmSoil (dry packed earth, small pebbles), Grass (forest floor: needles/humus/moss mix, grass tufts), Gravel (packed dirt road, gravel fraction), ShallowMud (brown, wet, smooth with slight ripples), DeepMud (darker, glossy, thick),
   Bog (very dark peat with greenish algae film), Sand/Silt (pale, ripples). Strong, readable colour differences between types (dry→wet→deep→bog get steadily darker, glossier, more saturated brown/green) because *reading the terrain is gameplay*. Plus a tileable macro-variation noise texture and a detail-normal texture.
2. **`GroundRenderer`** (MonoBehaviour) — `Build(GroundMap map)` / `Rebuild()`; creates GPU resources from the map: height texture (R32F or RFloat, clamp, bilinear, whole map), two control textures (RGBA8 × 2, from `weights`), params texture (RG8: extraDepth, baseWet); builds chunk objects.
   * Chunk system: world split into 32 m × 32 m chunks. Shared flat grid meshes per LOD (local XZ only; heights come from the height texture in the vertex shader): LOD0 0.25 m (128×128 quads), LOD1 0.5 m, LOD2 1 m, LOD3 2 m, LOD4 4 m, each with a **skirt** (downward flange of ≥ 2 m on all four sides) to hide cracks between LODs. Each chunk = one `MeshRenderer` with the shared material and a `MaterialPropertyBlock`-free approach (SRP Batcher compatible; chunk origin comes from `unity_ObjectToWorld`). Use hysteresis; select LOD by distance to the main camera (~LOD0 ≤ 40 m, LOD1 ≤ 90 m, LOD2 ≤ 180 m, LOD3 ≤ 400 m, LOD4 beyond); update the selection at ~5 Hz (spread over frames, no per-frame allocations). Chunks beyond the camera far-plane distance are disabled. Provide `MaxDrawDistance`.
   * LOD0 must show the 0.25 m field detail; LOD1/2 also sample the field (with the same displacement) so ruts remain visible at 60-120 m.
   * `GroundColliderBuilder.Create(GroundMap)` — builds a Unity `Terrain` **collider only** (`TerrainData` created at runtime, resampled bilinearly to the nearest valid heightmap resolution 2^n+1 ≥ map size; `Terrain.drawHeightmap = false`; layer Terrain; never persisted as an asset). Used by rocks/logs/cargo; wheels do not use it.
3. **Shader `MudRunner/Ground`** (hand-written URP HLSL, `Assets/Game/Shaders/Ground.shader`), Forward lit path with: main light + additional lights + shadows (`_MAIN_LIGHT_SHADOWS`, cascades, soft shadows, `_ADDITIONAL_LIGHTS`), fog, SH/ambient GI, **ShadowCaster, DepthOnly and DepthNormals passes** (the displaced geometry must cast and receive correct shadows and work with SSAO).
   * Vertex: world position from chunk origin + local grid, macro height from the height texture (`SAMPLE_TEXTURE2D_LOD`), plus `dh` from `_MR_MudField` (bilinear, hardware filtering) weighted by a smooth window-border fade; skirt vertices (flag in UV or colour) drop by a fixed amount.
   * Fragment: surface layer blend from the two control maps + `Texture2DArray`s (world-space top-down UVs at two scales + macro noise to break tiling; fade to cheaper sampling with distance); triplanar or slope-based blend so steep slopes show rock instead of stretched textures; detail normal; normal = macro height normal (central differences in the height texture) combined with the field normal (central differences of `dh` at ±1 texel) so ruts are lit properly;
     wetness model: `wet = saturate(baseWet + _MR_Wetness·sensitivity + churn)`; wetter → darker albedo, higher smoothness (mud gloss), lower normal strength; ruts (dh < −0.03) get dark, wet, glossy look and **standing-water puddles** when `_MR_Wetness` is high (flat, mirror-like, darker, with ripple normals); berms/churned ridges a bit lighter and rougher; compaction darkens/smooths the rut floor slightly.
     Bog must look swampy (dark, sheen, green algae patches); shallow/deep mud clearly distinguishable; road/gravel pale and dry; grass visibly green. Debug mode (`_MR_DebugMode` float: 0 off, 1 = surface type colours, 2 = dh, 3 = churn) for QA screenshots.
   * Performance: SRP Batcher compatible (`CBUFFER` correct), one material, no per-pixel loops over more than 8 layers sampled sparingly (sample only layers with weight > 0.02 using branches or sample the 4 dominant), target ≤ 1.5 ms GPU on an RTX 5070 at 1080p.
4. **Capture harness** `Assets/Editor/Rendering/GroundRenderCapture.cs` — batch-mode method `MudRunner.EditorTools.GroundRenderCapture.Run` (run with `GFX=1 Tools/ub.sh <name> MudRunner.EditorTools.GroundRenderCapture.Run`): builds a demo `GroundMap` (rolling hills, a mud basin with all 8 surface types arranged as bands, a river-valley-like depression, a slope), installs `GroundService` + `GroundRenderer`, a directional light (sun low in the sky, shadows on) + skybox/ambient, a Camera, **carves synthetic wheel tracks into the field** with `MudField.CarvePatch` along a few paths (two parallel wheel ruts with side berms, a spun-out hole, a figure-8 of churned mud), then renders several views to PNG with a RenderTexture + `Texture2D.ReadPixels`: `Captures/ground_close_rut.png` (1.5 m above the ruts, looking along them), `ground_wide.png`, `ground_overview.png` (high altitude), `ground_lowsun.png`, and the debug modes. It also prints `[MudRunner]` lines with measured frame time (CPU ms of Camera.Render averaged over 60 renders) and triangle/chunk counts.
   Use the Unity runner `Tools/ub.sh` (see its header; only one Unity process may open the project, the script serialises access with a lock — never start Unity.exe yourself).

## 3. Acceptance criteria (verify them with the screenshots — look at the PNGs with the Read tool)
* Ruts/berms/spun-out holes are clearly visible as geometry and shading in the close and wide captures; no cracks/holes between chunk LODs; no visible popping seam at LOD0↔LOD1 borders; shadows fall into ruts correctly.
* The eight surface types are instantly distinguishable at 20-80 m distance in the overview capture; mud types look wet; puddles appear in ruts when `_MR_Wetness`=1.
* Tiling is not obvious; no shimmering on the horizon (mipmaps, fade of detail).
* The shader compiles without errors/warnings in Forward URP 17.6 incl. shadow/depth passes; works in the Editor, in batch with graphics, and in a player build.
* Zero per-frame GC allocations after build; chunk LOD update < 0.2 ms average.
* Documented in a short `Assets/Game/Runtime/Rendering/README.md` (how to use, shader properties, known limits).

## 4. Working rules
* Run `python -I Tools/qc.py` (≈10 s, no Unity) after every C# edit to catch compile errors; use `Tools/ub.sh` only for real Unity runs (shader compile, captures). Another worker may be using Unity: the script waits for the lock.
* Do NOT modify files outside your folders except the minimal `GroundService` extension described above and `TestArena` additions. Do not edit `ProjectSettings` or `Packages/manifest.json` (ask via your report). Do not touch Blender.
* Commit nothing (the lead commits). Report: files created, measured performance, screenshots produced, known limitations.
