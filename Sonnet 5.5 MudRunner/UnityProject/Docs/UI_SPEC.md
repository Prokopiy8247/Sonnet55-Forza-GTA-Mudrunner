# UI_SPEC — cameras, HUD, menus, debug/benchmark menu (contract for the UI worker)

Unity 6000.6, URP 17.6, C#. **Input System package only** (legacy `UnityEngine.Input` throws) – read devices directly (`Keyboard.current`, `Mouse.current`, `Gamepad.current`) like `PlayerVehicleInput` does.
UI toolkit: use **uGUI built from code** (Canvas + `UnityEngine.UI` + `TMPro` is available but the TMP essentials asset may be missing – prefer legacy `Text` with the built-in font `Resources.GetBuiltinResource<Font>("LegacyRuntime.ttf")`, or generate procedural sprites). The debug/benchmark menu may use IMGUI (`OnGUI`). A clickable UI needs an `EventSystem` with `InputSystemUIInputModule`.
Look and feel: dark translucent panels, amber/orange accent, clean sim-style gauges, readable at 1080p and 1440p (scale with `CanvasScaler`), safe margins. It will be recorded for YouTube: it must look deliberately designed, not like debug text.

## 1. Existing code to read first
`Assets/Game/Runtime/Game/GameManager.cs` (facade: `Player`, `Vehicles`, `World` (+`WorldPoint` teleports), `SpawnVehicle`, `SwitchPlayerVehicle`, `TeleportPlayer`, `RecoverPlayer`, events), `PlayerVehicleInput.cs` (key bindings + edge flags `pressedCamera/pressedMap/pressedHelp/pressedHeadlights`, `winchAxis`), `Vehicles/Vehicle.cs` (telemetry fields: `speedKmh`, `forwardSpeed`, `drivetrain` (rpm, `GearLabel`, `lowRange`, `awd`, `centreLock`, `axleLock[]`, `engineOn`, `mode`), `fuel`, `def.fuelCapacity`, `damage01`, `isStuck`, `wheels[]` (per wheel: `load`, `sinkage`, `slipRatio`, `soil.dominant`, `tractionUsage`, `grounded`), `winch` (`Attached`, `Tension`, `RopeLength`, `Distance`), `water` (`engineFlooded`, `inWater`, `floating`)), `Ground/GroundService.cs` + `GroundMap.cs` (surface lookup, `mudDepthScale`, `softnessScale`, `wetness`, `rutRelaxScale`), `Atmosphere/AtmosphereController.cs` (time of day, rain), `Objectives/ObjectiveManager.cs` (HUD-facing objective state), `Testing/BotDriver.cs`.

## 2. Deliverables (folders `Assets/Game/Runtime/UI/` and `Assets/Game/Runtime/CameraSystem/`, editor helpers in `Assets/Editor/UI/`)
1. **CameraRig** (replaces `SimpleChaseCamera`; GameBootstrap/GameSceneBuilder must install it on the Main Camera): modes cycled with `C` and by API `SetMode`: Chase (default; mouse orbit while right mouse button held or always-on with smooth auto-recentering behind the vehicle after 2 s idle; scroll wheel zoom 4–20 m; collision with terrain (GroundService height) and props (`SphereCast` on `GameLayers.CameraMask`); lag/smoothing tuned for heavy slow vehicles; slight look-ahead), Cockpit (at the vehicle's `Cam_Cockpit` empty if present else a def-based eye point; mouse look; head bob from suspension), Wheel close-up (orbits the selected wheel at 2–3 m so the suspension articulation and sinking tyres are visible – `[` / `]` or Tab-cycle selects wheel; auto frames the wheel + axle), Top/far, Free camera (WASD+mouse+shift, used by the debug menu). Smooth transitions (blend 0.4 s). Camera shake on hard impacts (subtle). FOV 60-75, speed-based.
2. **Hud** (code-built uGUI, only visible when a player vehicle exists): speedometer (km/h analog arc + digital), RPM gauge with redline, gear/range text (e.g. `3 | LOW`, `R`, `N`), indicators: AWD, front/rear/centre diff-lock lamps, engine on/off/flooded, handbrake, headlights; fuel gauge with litres and low-fuel warning; damage bar; winch panel (state, rope length, tension bar vs rating); inclinometer (pitch/roll degrees – gameplay relevant), compass strip with cardinal letters and markers for objective + named sites (`GameManager.World.points`), minimap + full map (`Tab`): render the `GroundMap` once per world into a texture (surface colours from `SurfaceDatabase.Table[i].tint` blended, height shading, `WaterMap` blue) – the full map shows routes/sites/objective/player arrow/other vehicles and can be panned/zoomed; objective panel (`ObjectiveManager`: title, detail, distance, time/fuel limits, cargo status); **stuck warning** (flashing banner when `Vehicle.isStuck`: hints diff lock / low range / winch / recover key); notification toasts (`Hud.Notify(string, float seconds)` static API); on-screen **control help** (`H`, also shown for the first 10 s of a session); surface readout (current surface type name under the vehicle + sinkage) as a small gameplay widget; FPS only in debug.
   **Physics overlay** (F2): per-wheel panel anchored near each wheel in screen space (project `Wheel.hubWorld`): load (kN), sinkage (cm), slip ratio, surface, traction-usage bar (green→red), plus a compact table at the side and engine/driveline numbers (rpm, torque, clutch slip, lock stress).
3. **Menus**: Pause menu (Esc: resume, controls, graphics quality low/med/high via `QualitySettings`, master volume, return to main menu, quit); simple **Main menu** shown at start (scene `Game` boots into it; options: Free drive – Wilderness, Free drive – Proving ground, Scenarios (list from a static `ScenarioCatalog` you define with ~3 entries: title/description/vehicle/world/difficulty – the lead's `ObjectiveManager` will consume the selection via `GameSession.Selected`), Vehicle choice (scout/utility/hauler with a little stat block built from `VehicleDefinition`: mass, tyre size, power, winch, fording), Quit). **Garage menu**: opens with Enter when the player vehicle is inside a garage site radius (sites arrive later via `WorldSites`, make it data-driven: `GarageZone` component with radius) – switch vehicle, refuel, repair, back.
4. **DebugMenu** (IMGUI window, toggle with backtick `` ` `` or F1; pauses vehicle input while a text field has focus), grouped sections, all of it functional:
   teleport (every `WorldData.points` entry + "Spawn point"), vehicle switch/spawn any vehicle (scout/utility/hauler), trailer/cargo buttons (call `MudRunner.Cargo.TrailerSystem.Instance` if present – a stub exists; null-safe), refuel, repair, flip-reset (`Vehicle.ResetUpright`), free camera, global mud depth multiplier (`GroundService.mudDepthScale` 0.2-3), softness multiplier (`softnessScale` 0.3-3), rut relax scale, rain on/off + rain intensity, wetness slider, time of day slider + time-lapse speed (`AtmosphereController`), toggles: physics overlay, collider/force gizmos (draw contact normals, per-wheel force vectors and the belly points with `GL` lines or a LineRenderer pool in the Game view), slow motion (0.1x/0.25x/0.5x/1x; scale `Time.timeScale` and keep `fixedDeltaTime` consistent), AWD/low range/diff-lock toggles, winch auto-anchor, show FPS (smoothed + 1% low), coordinates, current surface type + soil numbers under the vehicle, **“Run physics test suite”** button (calls `MudRunner.Testing.RuntimePhysicsSuite.Run()` if present – null-safe via reflection; the lead adds it later), mud-field debug view toggles (`_MR_DebugMode`: surface type / dh / churn if the ground shader supports them: `Shader.SetGlobalFloat("_MR_DebugMode", n)`).
5. **GameSceneBuilder** update (`Assets/Editor/GameSceneBuilder.cs`): add Canvas/EventSystem/Hud/DebugMenu/CameraRig bootstrap (preferably created at runtime by a `UiBootstrap` the `GameBootstrap` calls, so the scene stays tiny) and make `Tools/ub.sh <name> MudRunner.EditorTools.GameSceneBuilder.BuildAllFromCli` regenerate it.
6. **Verification**: a capture harness `Assets/Editor/UI/UiCapture.cs` + PlayMode test `Assets/Game/Tests/PlayMode/UiTests.cs`: start the Game scene (graphics on: `GFX=1 Tools/rt.sh ui1 UiTests` for tests with rendering; screenshots via `ScreenCapture.CaptureScreenshotAsTexture()` written to `Captures/ui_*.png`), drive the player vehicle a few seconds, capture: HUD chase view, cockpit view, wheel close-up, physics overlay, full map, debug menu, pause menu, stuck warning. LOOK at the PNGs (Read tool) and iterate until the UI looks good. Tests assert: no exceptions, HUD elements exist, camera modes switch, debug menu actions change the expected values.

## 3. Rules
* Own folders listed above; edit `GameManager.cs`, `GameBootstrap.cs`, `PlayerVehicleInput.cs` minimally (additive) if you need hooks. Do not change vehicle physics. The ground renderer, world builders, audio and atmosphere visuals are being written by other workers right now – code defensively (null-safe `Instance` checks) and do not depend on their unfinished classes at compile time.
* `python -I Tools/qc.py` after each C# edit (10 s, no Unity). Real Unity runs only through `Tools/ub.sh` / `Tools/rt.sh` (a lock serialises access; a run may wait for others). Never start Unity.exe yourself. If a compile error is in a file you do not own, wait 60-90 s and retry (it is another worker mid-edit). No `git commit`. No ProjectSettings/manifest edits (report needs). Don't touch Blender.
* Report: what was built, how to use, screenshots (paths) with your honest quality assessment, known gaps.
